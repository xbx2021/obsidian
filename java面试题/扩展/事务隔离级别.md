# 读已提交
## 时序流程图
```mermaid
sequenceDiagram
    participant 事务A
    participant 事务B
    participant 数据库
    
    Note over 事务A,事务B: 隔离级别：读已提交RC
    事务A->>数据库: 开启事务
    事务A->>数据库: select * from t where id>10
    数据库-->>事务A: 返回2条数据
    Note over 事务A: 第一次查询结束
    
    事务B->>数据库: 开启事务
    事务B->>数据库: insert id=11 新数据
    事务B->>数据库: commit提交事务
    Note over 事务B: 插入成功，无间隙锁阻挡
    
    事务A->>数据库: 再次执行同条件select
    数据库-->>事务A: 返回3条数据
    Note over 事务A: 同一事务，相同查询，数据变多→幻读
    事务A->>数据库: 提交事务
```
## 出现幻读核心原因

1. **RC 每次 SELECT 都会重新读取最新已提交快照**，不是事务启动时固定快照
2. **RC 下 InnoDB 只有行锁，没有间隙锁**，区间空白处可随意插入数据
3. 只能屏蔽脏读，**无法阻止其他事务新增、删除数据**，必然产生幻读

## 可重复读 对比（解决幻读）

- RR：事务内**首次查询固定快照**，普通快照读无幻读
- RR + 当前读：**临键锁 + 间隙锁**锁住查询区间，禁止插入新数据，彻底杜绝幻读


# 可重复读
## 时序流程图

```mermaid
sequenceDiagram
    participant 事务A
    participant 事务B
    participant 数据库
    Note over 事务A,事务B: 隔离级别：可重复读 RR(InnoDB默认)
    事务A->>数据库: 开启事务
    事务A->>数据库: select * from t where id>10
    数据库-->>事务A: 返回2条，生成事务一致性快照
    
    事务B->>数据库: 开启事务
    事务B->>数据库: insert id=11 新数据并commit
    
    事务A->>数据库: 再次同条件select查询
    数据库-->>事务A: 依旧返回2条(走旧快照)
    Note over 事务A: 快照读：前后数据一致，无幻读
    
    事务A->>数据库: 执行当前读 update/select ... for update
    Note over 事务A: 触发临键锁/间隙锁，锁住id>10区间
    事务B->>数据库: 尝试再插入新数据
    数据库-->>事务B: 阻塞等待，无法插入
    事务A->>数据库: commit释放锁
    数据库-->>事务B: 插入成功
```

## 核心要点

1. **快照读**：事务启动后首次查询确立数据视图，全程复用，其他事务新增提交也看不到，避免幻读
2. **当前读**：加排他锁 + 间隙锁，直接锁住查询范围的空闲位置，从物理层面禁止插入新数据
3. RR 既解决不可重复读，也彻底杜绝幻读

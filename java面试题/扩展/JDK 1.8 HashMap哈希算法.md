```java
int hash(Object key) { 
	int h = key.hashCode()； 
	return (h ^ (h >>> 16)) & (capicity -1); //capicity表示散列表的大小 
	}
```

# 逐行拆解 `return (h ^ (h >>> 16)) & (capacity - 1)` 计算逻辑
这是**JDK 1.8+ HashMap**的核心哈希取模算法，目的是**让哈希值分布更均匀、减少哈希冲突**，最终算出元素在散列表中的下标位置。
我把这行代码拆成**3步**，用最通俗的方式讲清楚每一步计算：

## 先明确变量含义
- `h`：`key.hashCode()` 的结果，是一个 **32位int整数**（范围：-2¹⁵ ~ 2¹⁵-1）
- `h >>> 16`：无符号右移16位
- `^`：按位异或运算
- `&`：按位与运算
- `capacity`：散列表大小，**必须是2的n次幂**（HashMap强制要求）

---

## 第一步：`h >>> 16` → 无符号右移16位
`>>>` 是**无符号右移**，规则：
1. 把32位int值的二进制，**整体向右移动16位**
2. 左边空出来的位置**全部补0**
3. 正数、负数右移结果一致（区别于带符号右移`>>`）

**作用**：把哈希值的**高16位**移动到低16位的位置。
> 举例：h = 0x7FFFFFFF（二进制：32位全1）
> h >>>16 = 0x00007FFF（高16位移到低16位，原高16位补0）

---

## 第二步：`h ^ (h >>> 16)` → 高低16位异或混合
`^` 是**按位异或**，规则：**相同为0，不同为1**
这一步是**哈希扰动**：把哈希值的**高16位和低16位混合**。

### 为什么要做这一步？
- 散列表大小通常不大，`hashCode()`的**高16位几乎用不上**
- 直接用低16位取模，冲突概率极高
- 异或混合后，**高16位的特征也参与到最终计算**，让哈希分布更均匀

**计算示例**：
h = 二进制 `1010 1100 0011 0101 1100 1010 0110 1001`
h>>>16 = 二进制 `0000 0000 0000 0000 1010 1100 0011 0101`
h ^ (h>>>16) = 高低16位逐位异或后的新哈希值

---

## 第三步：`& (capacity - 1)` → 计算最终下标
这是**代替取模运算`%`**的优化方案，效率远高于`%`。
因为 `capacity` 是**2的n次幂**，满足公式：
`hash % capacity = hash & (capacity - 1)`

### 计算规则（按位与`&`）：**同时为1才是1，否则为0**
### 关键特性：
1. `capacity` 是2的n次幂 → 二进制是 `1000...0`
2. `capacity -1` → 二进制是 `0111...1`（末尾全是1）
3. 按位与后，结果**一定在 0 ~ capacity-1 之间**，正好是散列表的下标范围

**举个直观例子**：
capacity = 16（2⁴）→ 二进制 `10000`
capacity -1 = 15 → 二进制 `01111`
任意哈希值和 15 做按位与，结果只能是 0~15，完美对应数组下标。

---

# 完整计算流程总结
1. **右移**：把哈希值高16位移到低16位
2. **异或**：高低16位混合，让哈希分布更均匀
3. **按位与**：快速算出 0~容量-1 的散列表下标

# 核心目的
- 替代低效的`%`取模，提升性能
- 混合高低位，**大幅减少哈希冲突**
- 保证结果落在散列表合法下标范围内

### 总结
1. 这行代码分**右移16位→异或混合→按位与取下标**三步计算
2. `h>>>16` 提取高16位，`^` 混合高低位让哈希更均匀
3. `&(capacity-1)` 是2的幂数组专用的高效取模方式
4. 最终结果就是元素在散列表中的**存储下标**

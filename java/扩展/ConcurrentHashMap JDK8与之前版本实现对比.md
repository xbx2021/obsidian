JDK 8 的 ConcurrentHashMap 是对 JDK 7（及更早）版本的**彻底重构**，核心从**分段锁（Segment）** 升级为 **CAS + synchronized 节点锁**，并引入**红黑树**，整体并发性能、内存效率和查询速度都有质的飞跃。

### 一、核心数据结构对比
#### JDK 7 (及更早)
**结构**：`Segment 数组 + HashEntry 数组 + 链表`
- **Segment**：继承自 `ReentrantLock`，是一个**分段锁**。默认 16 个 Segment，并发度固定为 16。
- **HashEntry**：每个 Segment 内部维护一个 `HashEntry[]`，冲突时用**链表**解决。
![](assets/ConcurrentHashMap%20JDK8与之前版本实现对比/file-20260513110805771.png)

#### JDK 8+
**结构**：`Node 数组 + 链表 / 红黑树`
- 直接使用**一维 Node 数组**作为存储，取消 Segment 分层。
- 冲突链表长度 **≥ 8 且数组长度 ≥ 64** 时，**链表转为红黑树**（查询从 O(n) → O(log n)）。
- 树节点数 **≤ 6** 时，退化为链表。

### 二、并发控制机制对比
#### JDK 7：分段锁 (Segment + ReentrantLock)
1. **定位**：计算 key hash → 定位到某个 Segment。
2. **加锁**：获取该 Segment 的 `ReentrantLock`（独占锁）。
3. **操作**：锁住**整个 Segment**（包含多个哈希桶），同 Segment 内所有操作串行。
4. **局限**：
   - 锁粒度偏大（锁一段，非单个桶）。
   - Segment 数量初始化后**不可扩容**，并发度被锁死。
   - 两层哈希计算，性能有损耗。

#### JDK 8：CAS + synchronized (头节点锁)
**读操作**：**完全无锁**
- Node 的 `val` 和 `next` 用 `volatile` 修饰，保证多线程可见性。
- 直接读取，无需加锁，读性能极高。

**写操作（put）**：**无锁 + 最小粒度锁**
1. 计算 hash，定位数组下标。
2. **桶为空**：用 **CAS** 无锁插入新节点。
3. **桶不为空**：
   - 仅用 `synchronized` 锁住**当前链表/红黑树的头节点**。
   - 锁粒度从“段”细化到“**单个哈希桶**”，不同桶完全并行。
4. **扩容中**：遇到 `ForwardingNode` 标记，线程**协助扩容**，不阻塞。

### 三、关键功能差异对比
#### 1. 扩容机制
- **JDK 7**：
  - 单个 Segment 独立扩容。
  - 全局扩容需遍历所有 Segment，效率低。
- **JDK 8**：
  - **多线程协同扩容**。
  - 扩容时用 `ForwardingNode` 标记旧桶，读写可继续。
  - 每个线程负责迁移一组桶，利用哈希表容量为 **2 的幂**特性快速重定位。

#### 2. 元素计数 (size())
- **JDK 7**：
  - 需**依次锁住所有 Segment** 累加计数。
  - 高并发下非常慢，是性能瓶颈。
- **JDK 8**：
  - 借鉴 `LongAdder` 思想，用 `baseCount + CounterCell[]` 分散计数。
  - **无锁统计**，高并发下性能极大提升。

#### 3. 锁选择
- **JDK 7**：`ReentrantLock`（需手动 lock/unlock，功能强但开销大）。
- **JDK 8**：`synchronized`
  - JVM 级优化（锁升级：偏向 → 轻量 → 重量）。
  - 无需额外对象头，**更省内存**。
  - JVM 持续优化，高并发下性能优于 `ReentrantLock`。

### 四、总结：核心差异表
| 维度 | JDK 7 (及更早) | JDK 8+ |
|:--- |:--- |:--- |
| **核心结构** | Segment数组 + HashEntry数组 + 链表 | Node数组 + 链表/红黑树 |
| **锁机制** | 分段锁（Segment，ReentrantLock） | CAS + synchronized（头节点锁） |
| **锁粒度** | 粗（整个Segment） | 极细（单个哈希桶/头节点） |
| **并发度** | 固定（默认16，不可扩容） | 动态（数组长度，可扩容） |
| **冲突处理** | 仅链表（长链查询慢） | 链表 + 红黑树（≥8树化） |
| **读操作** | 部分需加锁 | **完全无锁**（volatile可见性） |
| **扩容** | 单线程Segment独立扩容 | **多线程协同**，不阻塞读写 |
| **size()** | 锁全段，性能差 | 无锁（baseCount+CounterCell） |
| **内存** | 两层结构，Segment开销大 | 单层结构，内存更紧凑 |

一句话概括：
**JDK 7 是“分段加锁”的折中方案，JDK 8 是“无锁 + 最小粒度锁 + 红黑树”的极致优化，高并发下吞吐量和延迟全面领先。**

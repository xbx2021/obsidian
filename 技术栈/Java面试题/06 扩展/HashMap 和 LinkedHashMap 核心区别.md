
这两个都是 Java 中**Map 接口**的常用实现类，**核心区别只有一个：是否保证遍历顺序**，再延伸出底层结构、性能、使用场景的差异。

## 一、一句话核心区别
- **HashMap**：**无序**，不保证元素的存储/遍历顺序，顺序会随着扩容、插入操作改变。
- **LinkedHashMap**：**有序**，继承自 HashMap，**额外维护了一个双向链表**，**保证遍历顺序 = 插入顺序**（也可设置为访问顺序）。

---

## 二、详细对比表
| 特性 | HashMap | LinkedHashMap |
|------|---------|---------------|
| **底层结构** | 数组 + 链表/红黑树 | 数组 + 链表/红黑树 **+ 双向链表** |
| **遍历顺序** | **无序**（随机） | **有序**（默认插入顺序，可改访问顺序） |
| **性能** | 更高（无额外链表开销） | 略低（维护链表需要微小开销） |
| **内存占用** | 更小 | 稍大（每个节点多存储前后指针） |
| **线程安全** | 不安全 | 不安全 |
| **允许键值为null** | 允许（key最多1个null，value多个null） | 允许 |
| **特有功能** | 无 | 可实现**LRU缓存**（按访问顺序淘汰） |

---

## 三、关键细节解析
### 1. 遍历顺序（最直观区别）
**HashMap**
```java
Map<String, Integer> map = new HashMap<>();
map.put("张三", 1);
map.put("李四", 2);
map.put("王五", 3);
// 遍历结果：顺序随机，可能是 李四、张三、王五（每次运行都可能变）
```

**LinkedHashMap**
```java
Map<String, Integer> map = new LinkedHashMap<>();
map.put("张三", 1);
map.put("李四", 2);
map.put("王五", 3);
// 遍历结果：固定为 张三 → 李四 → 王五（插入顺序）
```

### 2. 底层结构差异
- HashMap：通过哈希表存储，只根据哈希值定位元素，**不记录顺序**。
- LinkedHashMap：在 HashMap 基础上，**给每个节点加了 before/after 指针**，串成双向链表，专门用来记录插入/访问顺序。

### 3. 性能与内存
- HashMap：无额外操作，**读写速度更快、占用内存更小**。
- LinkedHashMap：每次增删改都要同步维护双向链表，**性能略差、内存稍高**，但差距极小，日常开发几乎无感知。

### 4. 唯一的高级特性：LRU 缓存 
LinkedHashMap 可以开启**访问顺序**模式（`accessOrder = true`）：
- 越近被访问（get/put）的元素，越排在链表尾部；
- 最久未被访问的元素排在头部，可自动淘汰，**完美实现 LRU 缓存算法**。
👉 **HashMap 完全做不到**。

## 四、开发中怎么选？
1. **绝大多数场景用 HashMap**：不需要保证顺序、追求极致性能，优先选 HashMap。
2. **需要保证遍历顺序用 LinkedHashMap**：比如需要按插入顺序展示数据、日志记录、有序配置等。
3. **要做缓存用 LinkedHashMap**：实现 LRU 缓存策略，这是它的专属场景。

---

### 总结
1. **核心**：HashMap 无序，LinkedHashMap **有序（插入/访问顺序）**；
2. **结构**：LinkedHashMap = HashMap + 双向链表；
3. **性能**：HashMap 更快，LinkedHashMap 略慢；
4. **选型**：无序选 HashMap，有序选 LinkedHashMap，做缓存选 LinkedHashMap。

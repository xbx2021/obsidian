## **依赖反转原则（Dependency Inversion Principle）** 核心就两句话：

1. 高层模块不依赖低层模块，**都依赖抽象（接口/抽象类）**
2. 抽象不依赖细节，**细节实现依赖抽象**

---

## 一、违反DIP（错误写法）
高层`电脑`直接依赖**具体实现类**机械键盘，耦合死，换键盘要改电脑源码。

```java
// 低层模块：具体机械键盘
class MechanicalKeyboard {
    public void input() {
        System.out.println("机械键盘敲击输入");
    }
}

// 高层模块：电脑 直接依赖具体实现类
class Computer {
    // 强依赖具体类，写死了
    private MechanicalKeyboard keyboard = new MechanicalKeyboard();

    public void work() {
        keyboard.input();
    }
}

// 测试
public class BadTest {
    public static void main(String[] args) {
        Computer computer = new Computer();
        computer.work();
    }
}
```

**问题**：想换薄膜键盘、蓝牙键盘，必须修改`Computer`类代码，违背开闭原则、依赖倒置。

---

## 二、遵守DIP（标准正确写法）
### 1. 抽象层：定义键盘接口
```java
// 抽象接口：抽象层
public interface Keyboard {
    void input();
}
```

### 2. 低层细节：实现抽象接口
```java
// 低层实现：机械键盘
public class MechanicalKeyboard implements Keyboard {
    @Override
    public void input() {
        System.out.println("机械键盘敲击输入");
    }
}

// 低层实现：薄膜键盘
public class MembraneKeyboard implements Keyboard {
    @Override
    public void input() {
        System.out.println("薄膜键盘静音输入");
    }
}

// 新增：蓝牙键盘，不用改电脑代码
public class BluetoothKeyboard implements Keyboard {
    @Override
    public void input() {
        System.out.println("蓝牙无线键盘输入");
    }
}
```

### 3. 高层模块：依赖抽象接口，不依赖具体
```java
// 高层模块：电脑 → 依赖Keyboard抽象，不依赖具体键盘
public class Computer {
    // 依赖抽象接口
    private Keyboard keyboard;

    // 构造器注入抽象
    public Computer(Keyboard keyboard) {
        this.keyboard = keyboard;
    }

    public void startWork() {
        keyboard.input();
    }
}
```

### 4. 测试使用
```java
public class DIPTest {
    public static void main(String[] args) {
        // 随时切换不同键盘，无需改Computer源码
        Computer c1 = new Computer(new MechanicalKeyboard());
        c1.startWork();

        Computer c2 = new Computer(new MembraneKeyboard());
        c2.startWork();

        Computer c3 = new Computer(new BluetoothKeyboard());
        c3.startWork();
    }
}
```

---

## 三、为什么叫「依赖反转」

- 错误写法：  
  高层Computer → 依赖 → 低层MechanicalKeyboard  

- 正确写法：  
  高层Computer → 依赖 → 抽象Keyboard  
  低层MechanicalKeyboard → 依赖 → 抽象Keyboard  

**原本高层依赖低层，现在高低层都依赖抽象，依赖关系被反转**。

---

## 四、实际开发意义

1. 新增实现类不用改高层代码，符合**开闭原则**
2. 面向接口编程，方便Spring依赖注入
3. 易于单元测试，可随便写Mock实现类
